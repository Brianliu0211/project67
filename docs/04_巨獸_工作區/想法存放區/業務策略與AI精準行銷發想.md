# 💡 業務策略與 AI 精準行銷發想

本文件整理了專案人員於 2026-07-31 對於 AI 語音提取、拜訪狀態定義、數據戰情室（老手視角）以及「社會議題聯動精準行銷」的腦力激盪想法。

---

## 1. AI 語音輸入與「模糊/未提及欄位」處理機制

為了實現「用說的代替手動填表」這一核心賣點，AI 在處理使用者口語輸入時，必須建立一套清晰的判斷規則，以處理灰色地帶：

### 🔍 痛點與挑戰
使用者口語輸入往往是片段、模糊且不完整的。例如表格有 20 個欄位，使用者可能在語音中只提到了 1 個（如：「今天找陳小姐聊得很好，她下週要出國」），AI 該如何處理剩餘 19 個欄位？

### 🛠️ 建議的 AI 處理規則
1.  **「非破壞性」局部更新**：
    *   AI 只提取有明確提及的欄位（如：備註與出國時間），剩餘未提及的欄位在資料庫中**保持原樣（不覆寫、不猜測）**。
2.  **灰色地帶與漏填提示 (UI 反饋)**：
    *   在 App 介面上，若 AI 判定有高度關聯但語音未明說的欄位，可以以半透明或小紅點高亮提示業務：「*AI 偵測到陳小姐下週出國，是否需要為她新增『旅平險』標籤與出國行程？*」讓業務一鍵確認，而非強行寫入。
3.  **結構化欄位外的一律歸入「條列式備註」**：
    *   無法歸類入固定欄位（如電話、Email）的碎屑資訊，由 AI 自動整理成**條列式 (Bullet Points)** 寫入備註。
    *   備註中應包含這次拜訪的客觀結果：是成功還是失敗、哪裡 OK 哪裡不 OK、有沒有超出預期。

## 2. 拜訪形式與狀態定義

在將語意轉化為數據前，必須先在資料庫與 UI 上對「拜訪」進行基本定義，才能產生有意義的統計：

*   **拜訪形式 (Visit Types)**：首談、解說建議書、要保送件、照會補件、售後服務、隨機拜訪。
*   **拜訪結果 (Visit Outcomes)**：
    *   `成功`（達成當次拜訪目的，如收件成功）。
    *   `不OK / 拒絕`（客戶當下拒絕或意願低）。
    *   `待跟進`（需再次拜訪或補件）。
    *   `超乎預期`（客戶主動詢問其他險種或轉介紹新客戶）。

## 3. 數據戰情室：客戶畫像與市場主流趨勢洞察 (Customer Portfolio & Trend Analytics)

戰情室的重點不僅僅是統計業務個人的「銷售漏斗活動量」（如拜訪次數、成交率），更核心的是**幫助業務代表透過自己手頭所有客戶的資料，看清「市場流行」與「客戶群體畫像」**。

### 📊 核心分析維度
1.  **主力客群畫像 (Demographics)**：
    *   系統自動交叉分析業務所有客戶的：**年齡分布區間**（例如：25-35 歲的新婚族群佔比 55%）、**職業類別比例**（例如：科技業或自營商居多）、**主要預算帶**。
    *   **業務價值**：讓業務一目了然「我正在服務哪些人」，協助調整自己的專業領域定位與話術。
2.  **主流保險產品趨勢 (Product Trends)**：
    *   統計所有客戶已購或詢問中的險種佔比（例如：最近「實支實付醫療險」與「美元儲蓄險」佔比大幅上升）。
    *   **業務價值**：找出熱門主流。例如系統發現「30-40 歲的工程師客戶中，有 80% 同時投保了某類防癌險」，業務就可以將這個「主流流行」作為拜訪其他科技業客戶時的切入點。
3.  **社會議題與客戶關注熱度 (Emerging Needs)**：
    *   AI 分析最近拜訪紀錄中被提及次數成長最快的關鍵字（如：地震、失能、理賠、通膨）。
    *   **業務價值**：當發生社會議題時，快速反饋客戶的整體憂慮傾向，做為當下策略調整的依據。

## 4. 社會議題聯動與「專案拜訪待辦清單」 (Project-based Visit Todo List)

保險政策與外部環境（如天災、高齡化政策）隨時在變。當有新事件發生時，業務員需要撈出特定客群，進行主動關懷或拜訪。這時候，系統提供「專案拜訪待辦清單」來協助業務完成批次跟進：

### 💡 實境案例：地震帶與高齡化政策
*   **情境 A (地震後關懷)**：最近剛發生大地震，業務篩選出「居住地在花蓮、台東且無地震險」的客戶。
*   **情境 B (長照福利關懷)**：政府推出最新 65 歲以上老人社會福利，業務撈出「年齡 > 65 歲」的客戶。

### 🛠️ 功能設計：記錄目的 (Why) 與客戶 Checklist
1.  **建立清單**：業務在篩選出這批客戶後，點擊「建立專案待辦清單」，系統會提示業務輸入 **「創建此清單的目的 (Why)」**（例如：*花蓮地震後火險/地震險關懷* 或 *7月份老人長照福利拜訪*）。
2.  **可勾選的 Checklist 形式**：
    *   清單儲存後，業務隨時可以在 Sidebar 點開檢視。
    *   頁面頂部會大大地顯示業務自己寫的**創建目的 (Why)**。
    *   下方是該專案**待拜訪客戶的勾選清單 (Checklist)**（例如：`[ ] 王大同`、`[x] 林小姐`），每打完電話或拜訪完一人，勾選即可標記為已處理。
3.  **業務價值**：業務代表能隨時知道「為什麼要建這個清單」、「哪些人已經聯絡了、哪些還沒有」，提供極佳的短期專案跟進視角。

## 5. 技術實現路徑 (Technical Implementation Path)

這些想法在我們現有的 **Flutter + Supabase + Gemini API** 環境下，其實現方式、架構與形式如下：

### 🛠️ 實現方式一：AI 語音模糊提取與「灰色地帶」判定
*   **技術方式**：**Supabase Edge Functions + Gemini Structured JSON Mode**。
*   **具體流程**：
    1.  **語音上傳**：Flutter 端錄製音檔（`.m4a` 或 `.mp3`），上傳至 Supabase Storage `voice-notes` 儲存桶。
    2.  **觸發 Webhook**：檔案上傳成功後，觸發 Supabase Database Webhook，調用內置的 Edge Function。
    3.  **語音轉文字與分析**：Edge Function 調用語音轉文字服務（如 OpenAI Whisper 或 Gemini 1.5 Flash 內置語音分析）取得逐字稿。
    4.  **語意提取與 JSON 輸出**：將逐字稿送給 Gemini，並使用 `Structured JSON Output` 規定回傳格式。
        *   **Prompt 設計**：我們在系統提示詞中規定：
            *   「如果語音中沒有提到客戶年齡，請在 JSON 中將 `age` 設為 `null`，不要猜測。」
            *   「將無法歸類的日常對話、心情、瑣事，條列式整理入 `notes_bullet_points` 欄位。」
            *   「判定是否有進度推移的暗示，若有，輸出 `suggested_stage` 與 `reason`。」
    5.  **前端 UI 呈現形式**：
        *   Flutter 監聽到資料庫 `reminders` 欄位更新後，在 App 首頁以一個 **「AI 助理卡片」** 的形式跳出通知，讓業務一鍵確認：「AI 建議將王大同進度更新為 [核保中]，是否套用？」

### 🛠️ 實現方式二：客戶屬性與市場趨勢統計分析
*   **技術方式**：**PostgreSQL Aggregations / View + Flutter Charts (fl_chart) + Gemini 語意彙整**。
*   **具體流程**：
    1.  **資料庫視圖建立 (Database Views)**：
        - 建立一個 `customer_demographics_view` 視圖，透過 SQL 的 `GROUP BY` 與聚合函數，動態計算當前業務客戶的年齡區間分布（運用生日或標籤分類）、職業分類比例、主要持有險種排行。
    2.  **主流趨勢即時撈取**：
        - 建立 `hot_products_view`，根據 `customers.tags` 或保單記錄，計算最近 3 個月內成長最快的標籤/險種。
    3.  **AI 語意趨勢分析**：
        - 定期（如每週）由 Edge Function 調用 Gemini API，讀取本週所有新增備註（`notes`）的關鍵字，提取出「本週關注焦點」（例如分析出近期客戶對『地震險/天災險』的討論度上升了 35%）。
    4.  **前端 UI 呈現形式**：
        - **戰情室頁面**：不再只是單調的業績長條圖，而是圓餅圖（客群年齡/職業分布）、主流險種佔比環狀圖，以及一個 **「AI 本週客群關注焦點」** 燈號卡片（如顯示：近期長照與天災議題熱度高，建議跟進）。

### 🛠️ 實現方式三：專案拜訪待辦清單之篩選與記錄
*   **技術方式**：**Supabase Tables + 複合 SQL 篩選器**。
*   **具體流程**：
    1.  **篩選器實作 (SQL Filter)**：
        *   在 Flutter 端的客戶管理頁面，以進階篩選抽屜 (Filter Drawer) 提供條件組合（年齡、地區、標籤等），點擊後拼接 SQL `SELECT` 送往 Supabase。
    2.  **資料表建模 (Tables)**：
        - `visit_projects`：儲存專案標題、**創建目的 (why)**、是否完成旗標。
        - `visit_project_customers`：關聯表，包括外鍵 `customer_id` 以及 `is_visited` (Boolean) 欄位。
    3.  **前端 UI 呈現形式**：
        *   篩選完客戶後，UI 頂部顯示「建立拜訪待辦清單」按鈕，點擊彈出 Dialog 輸入目的。
        *   在首頁/側邊欄新增一個「專案待辦」卡片展示區，點開即可檢視該清單，以 `ListTile` + `Checkbox` 的形式呈現客戶清單，讓業務代表能隨時勾選已聯絡的人。
