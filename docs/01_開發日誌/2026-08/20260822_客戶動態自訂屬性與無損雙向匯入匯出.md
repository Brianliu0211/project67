## 🎯 背景與動機
在真實商業保險場景中，不同業務員原先使用的工具（Google 試算表、微軟 Excel、舊 CRM）各自帶有不同數量與名稱的自訂欄位（業務 A 有 16 欄、業務 B 有 6 欄、業務 C 有 22 欄）。
舊版系統將未對照欄位一股腦打包塞進日常拜訪備註 (`notes`)，造成：
1. **備註被大量雜項欄位污染**，日常隨手記變得難以閱讀。
2. **無法無損匯出回原表格**：業務員在系統內新增、修改、刪除客戶後，匯出至 Excel 時，自訂欄位已無法獨立還原為對稱的試算表表頭。

### 階段 1: Schema & 資料庫層 [已驗證]
- 撰寫 Migration `supabase/migrations/20260822_add_customer_custom_attributes.sql`。
- 在 `customers` 表擴充 `custom_attributes JSONB DEFAULT '{}'::jsonb NOT NULL` 欄位與 GIN 索引。

### 階段 2: 服務與邏輯層 (`CustomerExportService`) [已驗證]
- 建立 `lib/services/customer_export_service.dart`：
  - **動態表頭聚合 (`extractAllCustomAttributeKeys`)**：動態掃描待匯出客戶名單，提取聯集所有自訂 Key。
  - **Formula Injection 防護 (`sanitizeFormula`)**：阻斷以 `=`, `+`, `-`, `@`, `\t`, `\r` 開頭之 DDE 惡意公式執行。
  - **XSS 跳脫 (`escapeHtml`)**：HTML 報表嚴格過濾特殊字元，報表零 Token 密鑰殘留。
  - **vCard 3.0 RFC 2426 折行與 CRLF (`foldVCardLine`)**：長內容每 75 字元自動折行，相容 iOS/Android 通訊錄匯入。
  - **可逆前綴還原機制**：自訂欄位同名時避開核心欄位加註 `自訂_`，再次匯入時自動剝除前綴還原原始 Key。

### 階段 3: UI 組件與視圖層 [已驗證]
- **`CustomerShareExportDialog`**：微動畫彈窗，支援 Excel (.xlsx)、UTF-8 BOM CSV (.csv)、vCard (.vcf)、Print-Ready HTML 報表 4 大格式。
- **`BatchImportCustomersDialog`**：Step 1/3/4 UI 承諾文字對齊，Step 3 新增 `自訂屬性 (JSONB)` 預覽欄位，解析邏輯結構化存入 `custom_attributes`。
- **`CustomerDetailSideSheet`**：新增「自訂擴充屬性」動態鍵值編輯面板（支援即時增刪改），Header 新增單一客戶名片匯出。
- **`CustomerManagementTab`**：多選浮動列新增「匯出選取 (N)」，全域匯出接軌真實彈窗；批次覆蓋匯入以 `localWorkingCustomers` 記憶體即時合併，阻斷重複覆蓋競態與靜默失敗。
