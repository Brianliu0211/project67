  2. **修改資料重新 Fetch**：在 [customer_management_tab.dart](file:///c:/GitHub/project67/lib/screens/customer_management_tab.dart) 中，新增、修改、刪除操作成功後，都會呼叫 `await _fetchCustomers();` 重新從資料庫獲取整份名單，而非在本地 State 直接更新對應的項目。
- **待辦細項**：

### 4. 支援 Google 帳號第三方登入與連結
- **描述**：
  提供使用者在註冊與登入時，能夠直接連結或透過 Google 帳號進行第三方登入（OAuth），以提升登入便利性並簡化註冊流程。
  **【高優先度擴充標註：Google API 整合預備】**
  本功能將作為未來以下進階應用的基礎，實作時需設計好 Token 傳遞與 Scopes 的彈性擴充：
  1. **Gmail 與 Google 行事曆雙向同步**：未來需要讀取/寫入行事曆事件（Scope: `https://www.googleapis.com/auth/calendar`），以及可能需要的郵件解析/跟進（Scope: `https://www.googleapis.com/auth/gmail.readonly`）。
  2. **Google Drive 備份與名片匯出**（對應功能 10）：需要儲存與修改使用者雲端硬碟檔案的權限（Scope: `https://www.googleapis.com/auth/drive.file`）。
- **實作步驟建議**：
  1. **Google Cloud Console 設定**：
     - 前往 Google Cloud Console 建立 OAuth 2.0 用戶端憑證（需包含 Web、Android、iOS 等平台憑證，依專案支援平台而定）。
     - 於憑證中啟用對應的 API 服務（Google Calendar API, Gmail API, Google Drive API）。
     - 設定授權的重新導向 URI（Redirect URI），指向 Supabase 的 Auth 回呼地址。
  2. **Supabase Console 設定**：
     - 在 Supabase Dashboard -> Authentication -> Providers 啟用 Google 登入。
     - 填入 Google OAuth 憑證（Client ID 與 Client Secret）。
     - 在 Supabase 設定中配置預設請求的 Scopes（如 profile, email），或於客戶端調用時動態傳入 `queryParams` 指定 Scopes。
  3. **Flutter 程式碼串接與 Token 管理**：
     - 在 [login_screen.dart](file:///c:/GitHub/project67/lib/screens/login_screen.dart) 增加「使用 Google 帳號登入/註冊」的按鈕。
     - 呼叫 `supabase.auth.signInWithOAuth` 進行 Google 驗證：
       ```dart
       await supabase.auth.signInWithOAuth(
         OAuthProvider.google,
         // 於 queryParams 中動態要求額外的授權範圍 (如雲端硬碟、日曆等)
         queryParams: {
           'scopes': 'https://www.googleapis.com/auth/calendar https://www.googleapis.com/auth/drive.file',
           'access_type': 'offline', // 確保取得 refresh token
           'prompt': 'consent',
         },
         redirectTo: kIsWeb ? null : 'my.scheme://login-callback', // 需依平台設定
       );
       ```
     - **Provider Token 處理機制**：登入成功後，Supabase 會將 Google 的 `provider_token` (Access Token) 與 `provider_refresh_token` (Refresh Token) 儲存在 Session 中。需要在 Flutter 端建立安全機制，在需要呼叫 Google API 時，透過 `supabase.auth.currentSession` 取得該 Token 並傳遞給 `googleapis` 用戶端。
- **待辦細項**：
  - [ ] 於 Google Cloud 啟用 Google Calendar API, Gmail API, Google Drive API 並設定憑證與 Redirect URIs。
  - [ ] 在 `login_screen.dart` 中刻劃 Google 登入按鈕 UI（遵循 Google 品牌標誌規範）。
  - [ ] 實作 `signInWithOAuth` 邏輯，加入動態 Scopes 與 offline access 參數。
  - [ ] 撰寫 API Token 管理工具類別，實現從 Supabase Session 提取 `providerToken` / `providerRefreshToken` 用於呼叫 `googleapis` 庫的驗證邏輯。

### 12. 資料垃圾桶與 30 天自動永久刪除功能 (Data Trash Bin with 30-Day Auto-Purge)
- **描述**：
  為了避免業務代表誤刪客戶資料或日程提醒，系統需要引入「垃圾桶（回收桶）」機制。當資料被刪除時，不直接從資料庫抹除，而是標記為刪除並移至垃圾桶。若超過 30 天未被使用者「復原」，系統應自動進行永久刪除。
- **實作步驟建議**：
  1. **資料庫結構調整**：
     - 在 `customers` 與 `reminders` 等表新增 `deleted_at` (TIMESTAMPTZ, 可為空) 欄位。當此欄位有值時代表資料已被軟刪除（移至垃圾桶）。
     - 更新 RLS 政策，確保正常查詢只會讀取 `deleted_at IS NULL` 的資料。
  2. **自動清理排程 (pg_cron)**：
     - 在 Supabase 啟用 `pg_cron` 擴充套件，設定一個每日排程任務，自動執行 SQL 刪除超過 30 天的軟刪除資料：
       ```sql
       DELETE FROM public.customers WHERE deleted_at < NOW() - INTERVAL '30 days';
       ```
       *(註：由於關聯表 `reminders` 已設定 ON DELETE CASCADE，當客戶被永久刪除時，其提醒也會被自動一併清除。)*
  3. **前端 UI 與邏輯優化**：
     - 將原本 App 的「刪除」操作修改為將 `deleted_at` 設為當前時間（軟刪除），並給予 Toast 提示。
     - 在側邊欄或設定中新增「垃圾桶」專區，展示所有 `deleted_at IS NOT NULL` 的客戶與行程。
     - 垃圾桶內提供「復原（將 `deleted_at` 設回 NULL）」與「手動立即永久刪除」兩個按鈕。
- **待辦細項**：
