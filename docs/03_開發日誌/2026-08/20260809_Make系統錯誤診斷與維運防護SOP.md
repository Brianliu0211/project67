# 📅 [2026-08-09] - 【模組一 / 模組二】Make.com 系統錯誤診斷、告警機制與維運防護 SOP

> **執行狀態**：🟢 已部署線上運作 (Make.com Scenario & 系統維運防護機制)

## 🎯 實作成果摘要
建立系統級維運防護機制，防止 Make.com Scenario 因未捕捉的連續錯誤遭系統自動關閉（Active: OFF）。同步建立「4 大系統錯誤診斷分類矩陣」與「雙重告警 SOP (Dual Alert System)」，大幅提升測試與線上營運的可觀測性（Observability），消弭用戶端 LINE 訊息無回應（已讀不回）的資訊盲區。

---

## 🔍 一、 測試痛點與問題分析 (Background & Pain Points)
在系統測試與親友體驗期間發現以下營運痛點：

1. **Scenario 遭自動停用（Deactivated）**：Make.com 若遇到未捕捉的連續模組錯誤（如未過濾 `follow` / `unfollow` 事件或 API 逾時），系統會啟動保護機制自動將 Active 開關切換為 OFF。
2. **資訊盲區與體驗受損**：當 Scenario 停擺時，測試親友在 LINE 傳送訊息或點選選單會陷入「完全無反應（已讀不回）」的狀態；開發者若未及時主動登入 Make 後台，無法即時知情並修復。

---

## 📊 二、 系統錯誤類型分類與診斷指南 (Error Classification Matrix)
為確保開發團隊與維運人員在收到告警時能「秒懂錯誤類型並精準修復」，制定以下 4 大錯誤分類矩陣：

| 錯誤類別 (Error Type) | 觸發原因 (Root Cause) | LINE 使用者看到的現象 | 開發者告警管道 (Notification) | 標準處理 SOP (Remediation) |
| :--- | :--- | :--- | :--- | :--- |
| **【類別 1】Scenario 遭系統自動停用** | 流程中有未捕捉的模組錯誤，且連續發生（如未過濾 `follow` / `unfollow` 事件）。 | 傳訊息或點選單後完全無反應（已讀不回）。 | Make 系統自動寄送 Email：<br>`🔴 The scenario ... has been stopped` | 1. 登入 Make 手動點擊 Active 重開。<br>2. 檢查 History 補齊 Filter 或 Error Handler。 |
| **【類別 2】Make Operations 額度耗盡** | 本月 1,000 次免費 Operations 額度耗盡。 | 傳訊息或點選單後完全無反應。 | Make 寄信提醒：<br>`Operations quota reached` | 匯出 Scenario JSON 匯入至備用 Make 帳號，或升級方案。 |
| **【類別 3】AI Agent 點數/模型報錯** | OpenAI API 餘額不足、模型超時或 Prompt 格式錯亂。 | 收到系統自動發送的備援 LINE 訊息：<br>「目前 AI 諮詢熱絡，額度暫時用完...」 | 觸發備援 Gmail 警報信：<br>`⚠️ [系統警報] LINE AI 客服額度不足...` | 檢查 OpenAI / Make AI 點數餘額，或修正 Prompt。 |
| **【類別 4】LINE API 憑證失效** | LINE Channel Access Token 被重新發行或連線中斷。 | 傳訊息後無反應，Make 紀錄顯示 `401 Unauthorized`。 | Make History 顯示 `401 Unauthorized` 紅色錯誤標籤。 | 至 LINE Developers 重新複製 Channel Access Token，更新 Make Connection。 |

## 🛡️ 三、 系統維運防護與防爆設定 SOP (System Fortification SOP)

### 1. 防護 SOP 1：開啟「錯誤暫存」防止 Make 自動關閉 Scenario
- **操作路徑**：Make.com 編輯器左下角 ➔ 點擊 ⚙️ **Scenario settings**。
- **設定變更**：將 **Store incomplete executions** 從 `No` 切換為 `Yes`。
- **維運效益**：當系統遇到偶發性單次錯誤時，Make 會將錯誤資料暫存於 **Incomplete executions** 備查，確保 Scenario 繼續保持在 **Active (ON)** 狀態，不再自動停擺關閉。

### 2. 防護 SOP 2：雙重告警機制 (Dual Alert System)
- **第一重（Make 系統級告警）**：Make 官方會在 Scenario 停用或 Operations 額度達 80% / 100% 時，自動發送系統郵件至開發者信箱 (`brain2013bb@gmail.com`)。
- **第二重（模組級主動告警）**：在 Make AI Agent 的 Error Handler 後端掛載 `Gmail - Send an Email` 模組，一旦 AI 思考報錯或 API 逾時，0.1 秒內主動發送 `⚠️ [系統警報] LINE AI 客服額度不足...` HTML 郵件，達到 24 小時全天候無死角監控。

## 🚦 團隊協作與驗證指南 (Verification Plan)
- **維運人員檢查點**：
  1. 若收到 Make 官方寄發之 `The scenario has been stopped` 郵件，對照【類別 1】SOP 登入 Make.com 檢視 History 並重新啟動 Active。
  2. 若收到 `⚠️ [系統警報]` 郵件，對照【類別 3】SOP 檢視 OpenAI 帳戶點數餘額或 Prompt 邏輯。
  3. 定期至 Make.com 左側選單 **Incomplete executions** 檢查是否有暫存的失敗執行紀錄並進行 Re-run 測試。
