# ⌨️ 開發人員快捷指令手冊 (Developer Shortcuts)

為了提高開發效率並建立防呆機制，專案協作中定義了數個與 AI 助理對話的「快捷指令」。本手冊紀錄所有可用指令、輸入時機與 AI 對應的動作。

---

| :--------- | :------------- | :---------------------------------------------------------------- | :------------------- |
| **`開工`**   | 開始編寫新功能前       | 前置安全檢查、確認身分、靈感巡檢、選擇任務並進行 **4階段大任務微型拆解** 與分支指引                  | 引導 GitHub Desktop 為主 |

## 🛠️ 各指令詳細用法與流程

### 1. 「開工」
- **用法**：在與 AI 的對話開頭直接輸入 `開工`。
- **AI 動作**：
  1. **前置安全檢查**：自動檢查 Git 狀態，若偵測到本地有未提交變更，或前次分支未執行收工合併，將發出黃/橙色警告暫停開工程序。
  2. 透過 **`ask_question` 常駐彈窗** 讓您直接點選是 **蘿蔔 (lobo)** 還是 **巨獸 (beast)**，徹底免手動打字。
  3. **巡檢個人工作區新靈感**：唯讀讀取 `docs/01_蘿蔔_工作區/想法存放區/` 與 `docs/02_巨獸_工作區/想法存放區/`，若發現全新未討論靈感，詢問是否提報摘要至進度表萬能收件匣。（注意：AI 嚴禁修改或刪除人類工作區原始筆記）。
  4. 讀取 [進度.md](../進度.md) 並透過 **`ask_question` 常駐彈窗** 展示當前未完成任務供您點選。
  5. **大任務微型拆解協定 (Task Decomposition)**：選擇任務後，自動拆解為 `(1) Schema/RLS` $\rightarrow$ `(2) Service/邏輯層` $\rightarrow$ `(3) UI組件` $\rightarrow$ `(4) 驗證` 4 階段微型 Tickets 寫入 sub-task 脈絡。
  6. 提供如 `feature/username-featurename` 的分支命名建議與對應 GitHub Desktop 切換步驟。

### 2. 「收工」
- **用法**：完成本地測試且編譯無誤後，輸入 `收工`。
- **AI 動作**：
  1. **檢查與自動修復 Git 分支狀態 (Branch Safeguard & Auto-Switch)**：
     - 自動檢查當前 Git 分支與變更檔案：
       - 🟢 **純文件修訂 (Fast-Track 快速通道)**：若變更 100% 僅為 `docs/` 或 `.md` 文件，AI **直接在背景執行 `git checkout main`** 自動切換回 `main` 主線。
       - 🔴 **程式碼修訂 (Standard PR 流程)**：若包含 `lib/` 程式碼但未部位於標準分支，AI **直接在背景執行 `git checkout -b feature/username-featurename`** 自動幫您建好並切換至對應特徵分支，免去手動負擔！
  2. **Quality Gate 4 項品質稽核**：強制檢查 (1) Supabase RLS 安全、(2) UI 規範/Toast 標準、(3) 工具包 `docs/工具包.md` 同步、(4) Null Safety / Exception 防護。
  3. 在 `docs/03_開發日誌/` 依規範自動新增開發日誌，末尾**必須帶入 `[Handoff 狀態條言]`**（載明狀態、核心決策與下一步）。
  4. 自動在 [進度.md](../進度.md) 中勾選完成的任務。
  5. 產生可直接複製的 Git Commit 訊息與對應之推送/合併引導。

### 3. 「精簡模式」 / 「詳細模式」
- **用法**：輸入 `精簡模式`（或 `caveman`）切換至高密度對話；輸入 `詳細模式` 切換回完整教學說明。
- **AI 動作**：
  - **精簡模式**：去除客套話與多餘排版，僅輸出程式碼、核心技術關鍵與實體檔案連結，極省 Token。
  - **詳細模式**：提供完整的脈絡說明與步驟引導。

### 4. 「讓我看看」
- **用法**：輸入 `讓我看看` 請求網頁預覽。
- **AI 動作**：在背景執行預覽伺服器啟動命令，並提供點擊連結。專案人員亦可在根目錄手動雙擊 [run_local_web.bat](../../run_local_web.bat) 啟動。

### 5. 「確認狀況」
- **用法**：在開發過程中，若對目前的代碼方向有疑慮，輸入 `確認狀況`。
- **AI 動作**：進入安全防禦狀態，停止所有寫入與指令，並彙整：
  - 目前的任務進度。
  - 目前本機已修改的檔案清單與變更摘要。
  - 接下來 AI 預期要修改的內容與行為變化。

### 6. 「對齊」
- **用法**：當大模組功能開發完畢，或想要更新維護公共規格文件時，輸入 `對齊`。
- **AI 動作**：
  1. 對比現有程式碼、Supabase Schema 與 `docs/進度.md`。
  2. **廢棄資訊清掃 (Deprecation Sweep)**：清掃已被廢棄或取代的舊欄位、舊 SOP 與陳舊規範，避免規格書堆疊雜訊。
  3. **SSOT 全套規格對齊**：自動補全並對齊 [main_spec.md](main_spec.md)（主系統規格書）、[開發人員快捷指令.md](開發人員快捷指令.md) 與 [開發人員手冊.md](開發人員手冊.md) 全套公共規格文件。

### 7. 「book」
- **用法**：想要瞭解全專案的核心文件架構與連動關係時，輸入 `book`。
- **AI 動作**：
  1. 輸出 Mermaid 視覺化文檔關係圖。
  2. 條列說明 4 種連動型態（雙向自動對齊、單向唯讀巡檢、按需對齊、里程碑自動備份）。

### 8. 「自我修復」
- **用法**：當發現 AI 的執行邏輯有瑕疵、或者出現與原本系統設計相違背的特殊情況時，輸入 `自我修復`。
- **AI 動作**：
  1. **根因剖析**：條列說明預期設計與實際發生的矛盾與邏輯漏洞。
  2. **修復底層 SSOT 規則**：即刻修改 [.agents/AGENTS.md](../../.agents/AGENTS.md) 實體運作條文，確保邏輯閉環無死角。
  3. **廢棄資訊清掃 (Deprecation Sweep)**：巡檢並清理陳舊廢棄條文與矛盾邏輯。
  4. **全套雙向對齊**：同步修訂 [開發人員快捷指令.md](開發人員快捷指令.md)、[開發人員手冊.md](開發人員手冊.md) 與 [main_spec.md](main_spec.md)。
  5. **報告結果**：向專案人員摘要修復了哪些規則條文、清掃了哪些廢棄資訊，並說明全新防呆邏輯。

## 🛡️ 核心防護：反向專業防護與嚴謹架構設計協定
- **嚴禁敷衍型偷懶/捷徑寫法**：所有權限與組件必須符合現實商業軟體架構，嚴禁硬塞違背邏輯的開關按鈕。
- **反向專業質疑**：AI Agent 必須主動站出來提問邊界漏洞、使用者情境與安全風險，絕不盲目下單。
- **架構規劃優先**：大型或涉及權限、DB 的變更，必須先產出對照矩陣與路由藍圖，確認無誤後始得開發。
