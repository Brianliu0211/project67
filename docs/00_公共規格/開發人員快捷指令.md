# ⌨️ 開發人員快捷指令手冊 (Developer Shortcuts)

為了提高開發效率並建立防呆機制，專案協作中定義了數個與 AI 助理對話的「快捷指令」。本手冊紀錄所有可用指令、輸入時機與 AI 對應的動作。

---

## 🧭 快捷指令快速對照表

| 指令名稱       | 輸入時機           | AI 執行的主要動作                                                        | 備註                   |
| :--------- | :------------- | :---------------------------------------------------------------- | :------------------- |
| **`開工`**   | 開始編寫新功能前       | 確認開發者身份、展示未完任務、給予分支建議與開工 Git 指令                                   | 引導 GitHub Desktop 為主 |
| **`收工`**   | 開發完畢、準備提交時     | 自動建立開發日誌、更新進度表、生成 Commit 訊息與合併 PR 引導                              | 自動化流程整合              |
| **`讓我看看`** | 想在本地看網頁測試版時    | 自動在背景啟動預覽伺服器並提供 [http://localhost:8080](http://localhost:8080) 連結 | 便於快速測試與展示            |
| **`確認狀況`** | 迷失方向或懷疑 AI 誤解時 | **啟動安全凍結**，只讀不寫，列出已改檔案、後續變化並引導確認                                  | **安全手煞車**            |
| **`對齊`**   | 想要主規格書反映最新狀態時  | **巡檢對齊**，比對現有代碼與進度表，將最新欄位與模組補全至 `main_spec.md`                    | **憲法級對齊警衛**          |
| **`book`** | 想瞭解全專案文檔連動關係時  | **渲染文檔地圖**，輸出 Mermaid 關係圖與 4 種連動型態對照表                             | **文檔全景導覽**           |
| **`自我修復`** | 發現邏輯問題或規則與原設計矛盾時 | **自我剖析與規則修復**，找出邏輯漏洞、修訂 `AGENTS.md` 規則並全套同步對齊規範文檔                      | **規則自我診斷與淨化**        |

---

## 🛠️ 各指令詳細用法與流程

### 1. 「開工」
- **用法**：在與 AI 的對話開頭直接輸入 `開工`。
- **AI 動作**：
  1. **前置安全檢查**：自動檢查 Git 狀態，若偵測到本地有未提交變更，或前次分支未執行收工合併，將發出黃/橙色警告暫停開工程序。
  2. 詢問您是 **蘿蔔 (lobo)** 還是 **巨獸 (beast)**。
  3. **巡檢個人工作區新靈感**：唯讀讀取 `docs/01_蘿蔔_工作區/想法存放區/` 與 `docs/02_巨獸_工作區/想法存放區/`，若發現全新未討論靈感，詢問是否提報摘要至進度表萬能收件匣。（注意：AI 嚴禁修改或刪除人類工作區原始筆記）。
  4. 讀取並顯示 [進度.md](../進度.md) 中的當前大模組未完成任務供您選擇。
  5. 提供如 `feature/username-featurename` 的分支命名建議與對應 GitHub Desktop 切換步驟。

### 2. 「收工」
- **用法**：完成本地測試且編譯無誤後，輸入 `收工`。
- **AI 動作**：
  1. **檢查與自動修復 Git 分支狀態 (Branch Safeguard)**：
     - 自動檢查當前 Git 分支與變更檔案：
       - 🟢 **純文件修訂 (Fast-Track 快速通道)**：若變更 **100% 僅為 `docs/` 或 `.md` 文件**，AI 明確提示與引導切換至 **`main`** 主線分支（可免發起 PR），並明確輸出 **目標分支: `main`**。
       - 🔴 **程式碼修訂 (Standard PR 流程)**：若包含 `lib/` 或 `pubspec.yaml` 等程式碼，且未處於標準特徵分支，AI 將自動依身分 (lobo / beast) 生成標準分支（如 `feature/lobo-featurename`）並引導/執行切換。
  2. **智慧 Git 變更檢視與提交分流**：
     - 🟢 **純文件模式 (Fast-Track)**：引導在 GitHub Desktop 將分支切換至 `main` 後，直接 Commit & Push 至遠端 `main`。
     - 🔴 **程式碼模式 (Standard)**：**強制要求**使用特徵分支，明確輸出該特徵分支名稱並提供 PR 合併引導。
  3. 在 `docs/03_開發日誌/` 依規範自動新增今日開發日誌。
  4. 自動在 [進度.md](../進度.md) 中勾選完成的任務。
  5. 產生可直接複製的 Git Commit 訊息與對應之推送/合併引導。

### 3. 「讓我看看」
- **用法**：輸入 `讓我看看` 請求網頁預覽。
- **AI 動作**：在背景執行預覽伺服器啟動命令，並提供點擊連結。專案人員亦可在根目錄手動雙擊 [run_local_web.bat](../../run_local_web.bat) 啟動。

### 4. 「確認狀況」
- **用法**：在開發過程中，若對目前的代碼方向有疑慮，輸入 `確認狀況`。
- **AI 動作**：進入安全防禦狀態，停止所有寫入與指令，並彙整：
  - 目前的任務進度。
  - 目前本機已修改的檔案清單與變更摘要。
  - 接下來 AI 預期要修改的內容與行為變化。

### 5. 「對齊」
- **用法**：當大模組功能開發完畢，或想要更新維護公共規格文件時，輸入 `對齊`。
- **AI 動作**：
  1. 對比現有程式碼、Supabase Schema 與 `docs/進度.md`。
  2. **廢棄資訊清掃 (Deprecation Sweep)**：清掃已被廢棄或取代的舊欄位、舊 SOP 與陳舊規範，避免規格書堆疊雜訊。
  3. **SSOT 全套規格對齊**：自動補全並對齊 [main_spec.md](main_spec.md)（主系統規格書）、[開發人員快捷指令.md](開發人員快捷指令.md) 與 [開發人員手冊.md](開發人員手冊.md) 全套公共規格文件。

### 6. 「book」
- **用法**：想要瞭解全專案的核心文件架構與連動關係時，輸入 `book`。
- **AI 動作**：
  1. 輸出 Mermaid 視覺化文檔關係圖。
  2. 條列說明 4 種連動型態（雙向自動對齊、單向唯讀巡檢、按需對齊、里程碑自動備份）。

### 7. 「自我修復」
- **用法**：當發現 AI 的執行邏輯有瑕疵、或者出現與原本系統設計相違背的特殊情況時，輸入 `自我修復`。
- **AI 動作**：
  1. **根因剖析**：條列說明預期設計與實際發生的矛盾與邏輯漏洞。
  2. **修復底層 SSOT 規則**：即刻修改 [.agents/AGENTS.md](../../.agents/AGENTS.md) 實體運作條文，確保邏輯閉環無死角。
  3. **廢棄資訊清掃 (Deprecation Sweep)**：巡檢並清理陳舊廢棄條文與矛盾邏輯。
  4. **全套雙向對齊**：同步修訂 [開發人員快捷指令.md](開發人員快捷指令.md)、[開發人員手冊.md](開發人員手冊.md) 與 [main_spec.md](main_spec.md)。
  5. **報告結果**：向專案人員摘要修復了哪些規則條文、清掃了哪些廢棄資訊，並說明全新防呆邏輯。
