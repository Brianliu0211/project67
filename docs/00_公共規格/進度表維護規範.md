# 📐 專案進度表維護與動態擴充規範

本文件定義 `insurance_helper` 專案之進度表 (`docs/進度.md`) 的結構化層級、命名規範、動態擴充機制與多管道連動原則。

---

## 📌 一、 進度表三層架構規範

專案進度表採用 **「大模組 ➔ 中模組 (Phase) ➔ 小任務」** 三層樹狀結構：

### 1. 第一層：大模組 (Major Module / Domain)
* **定義**：依據系統的核心業務領域劃分（例如：身分驗證、客戶庫、AI 語音、日曆排程等）。
* **命名格式**：`## 📌 模組 X：模組名稱 (English Name)`
* **編號原則**：大模組採用開放式整數遞增（`模組一`、`模組二` ... `模組 N`），不設上限。

### 2. 第二層：中模組 / 階段 (Phase / Sub-module)
* **定義**：代表該大模組底下的功能發展階段或版本迭代。
* **命名格式**：`### 🟢 Phase X.Y: 階段名稱 [狀態]`
* **版本迭代小數點原則**：
  * `Phase X.0`：基礎核心功能（例如：客戶基礎 CRUD）。
  * `Phase X.5`：體驗優化與 UI 擴充（例如：3D 翻轉卡片、照片上傳）。
  * `Phase X.8`：進階整合與數據分析（例如：AI 數據戰情室）。
* **歷史日誌相容（雙軌別名法）**：進度表主編號回歸整數（如 Phase 1, Phase 2），標題內保留過往小數點別名（如 `Phase 1 (含 1.5 體驗優化)`），確保過去 `docs/03_開發日誌/` 中的紀錄 100% 可被搜尋回溯，不產生版本名稱脫節。

### 3. 第三層：小任務 (Feature Task)
* **定義**：具體可執行的代碼或介面實作項目。
* **格式**：`- [x] 已完成任務` 或 `- [ ] 未完成任務`。

---

## 🔄 二、 進度表內部想法流轉與搬移機制

所有靈感的提出、評估與歸檔，其**實體搬移與狀態變更完全發生在 `docs/進度.md` 檔案內部**：

```
[個人工作區筆記 (人類領地)] ➔ (開工巡檢只讀取) ➔ [📥 待評估暫存區 (進度表底部)]
                                                     │
                                 ┌───────────────────┴───────────────────┐
                                 ▼                                       ▼
                       【採納】向上搬移並升格                 【不採用】向下搬移並歸檔
                    [📌 模組 X / Phase X.Y 任務]             [🗑️ 不考慮與歷史備忘區]
```

### 1. 📥 待評估與新想法暫存區 (Backlog / Incubator)
* 放置於 `docs/進度.md` 的檔案底部。
* 用於接收從個人工作區讀取、或是討論中剛萌芽但尚未確定範疇與模組的全新靈感。

### 2. 轉正與向上搬移 (Adopted / Promoted)
* 當暫存區中的想法經討論確定採納時，AI 會將該項目**從 `待評估暫存區` 剪切並向上搬移**至對應的大模組/Phase 區塊中，成為正式的開發任務。

### 3. 不採用與歸檔 (Rejected / Archived)
* 若討論後決定「不考慮 / 評估後不採用」，AI 會將該項目**從 `待評估暫存區` 剪切並向下搬移**至最底部的 **`🗑️ 不考慮與歷史備忘區`**，並附上短原因。
* **效益**：確保待辦清單保持 100% 乾淨，同時保留歷史決策紀錄供未來複查。

---

## 🛡️ 三、 人類工作區邊界與保護原則

* **保護原則**：`docs/01_蘿蔔_工作區/` 與 `docs/02_巨獸_工作區/` 屬於專案人員（人類）的私人思考領地。
* **AI 存取限制**：
  * AI 在「開工」或「討論」時，**僅能讀取 (Read-Only)** 個人工作區內容以進行摘要與同步。
  * **AI 嚴禁主動修改、刪除或剪切專案人員在個人工作區打的任何原始文字與筆記**。

---

## 🚀 四、 動態擴充機制（模組 N 原則）

若未來出現當初未預期的全新領域（例如：保險理算計算器、團隊權限管理、金流訂閱等）：
1. 絕不安裝強迫歸類至既有的 1~5 模組。
2. **直接建立全新大模組**（例如：`【模組六】保險理算計算器`）。
3. 初始階段設定為 `Phase 6.0`，持續遵循三層架構推進。
